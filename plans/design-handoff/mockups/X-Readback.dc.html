EXTENSION · PROJECT WINDOWS + SPLIT PANES · READ-BACK

One pane component, any number of windows

Both features rest on one idea: a Pane (header + SwiftTerm + footer) that shows one command. A window holds a split tree of panes; the single-pane shell is a tree of one. A command is attached to at most one pane anywhere in the app.
1 · PROJECT WINDOWS — WHAT I UNDERSTOOD
Extraction, not copies. The main window is the board; opening a project in its own window pulls it off the board until that window closes (or Move to Board). A project window is the project: a title-like header (icon, name, running count, start / stop / restart all, ⋯ menu), then its groups and commands at the top level, no rail, no project icon in pane bars. Windows reopen on launch, so the board can first paint with projects missing. States: deleted, config invalid, nothing running, empty board.
2 · SPLIT PANES — WHAT I UNDERSTOOD
2 to 4 panes, split right or down, each pane picks its command (empty-pane picker, header dropdown, drag a sidebar row onto a pane). Layouts: 2, 3 including one tall + two stacked, 4. Layout remembered per project. Divider, resize, obvious focus, close and maximize. Per-pane footer shrinks to a quarter window. Minimum pane size, below which split is refused. Same one-view-per-command rule.
DIRECTION PROPOSAL
One 36 pt pane bar, everywhere
The shell's 56 pt header becomes the same one-line bar used in splits: glyph · project icon · Group / command ▾ · status · actions. Folder moves to the footer. It sheds parts by width (full ≥ 560 pt, mid 360–560, min under 360). Option A on the next board; B and C are there to compare.
Focus is the accent, nothing else
The focused pane gets a 2 pt accent rule on its bar and full-contrast bar text; other bars drop to secondary. Terminal text is never dimmed, so logs stay readable. The sidebar selection follows the focused pane.
Moving, never mirroring
Claiming a command moves its terminal and leaves a placeholder where it was, with "Bring here". The same placeholder serves panes and windows; only the wording changes ("in pane 2" / "in the Kinpay window").

Header option A. These keys; ⌘W still closes the window. Layouts in app state, not config.yaml. Minimum pane 320 × 180 pt. Closing a pane never stops its command. Pane bars show a project icon only when the command belongs to a different project than the window's.
